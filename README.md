# 搞月供 V4.02

独立 macOS 应用，包含本模块完整业务、游戏场景和 WidgetKit 小组件。运行不依赖搞七廿三或其他六个应用；联动功能需要同时安装相关应用。

## 下载与安装

从 [Releases](https://github.com/UCASerYff/GaoYueGong/releases/latest) 下载 `GaoYueGong-4.02.zip` 和同名 `.sha256` 文件。仓库保存源码，安装包作为 Release 附件单独发布。

1. 支持 macOS 14 或更高版本、Apple Silicon；暂未提供 Intel 版本。
2. 解压 ZIP，将 `搞月供.app` 拖入“应用程序”文件夹。
3. 如果 macOS 拦截打开，请先确认软件来源，再进入“系统设置 → 隐私与安全性”，允许该应用打开。发行包使用 Apple Development 签名，未做 Apple 公证。
4. 安装后运行一次，再从系统小组件列表添加本应用的小组件。整合版的小组件需要重新添加。

下载后将 ZIP 与校验文件放在同一目录，运行 `shasum -a 256 -c GaoYueGong-4.02.zip.sha256` 核验安装包。

## 功能

- 管理订阅、账单、续费、支付确认、权益与待办提醒。
- 可将确认的支付同步到搞积蓄；入账需明确绑定真实扣款账户。
- 贝塔的猫之家：喂食、家具、任务和升级，布局模式控制家具移动。

- 从菜单或 ⌘, 打开设置，提供外观、模块设置、备份与恢复。
- 扣款与权益小组件采用均衡的上下留白，显示近期扣款及更新时间。
- 新增独立「权益打卡」小组件（小号 / 中号）：显示本期已完成与待领取数量，可直接记录打卡，点开进入权益页；支持隐私模式。打卡记录会同步到已打开的主应用。
- 小组件打卡仅记录领取状态，仍需在对应平台实际领取权益。

## 用户数据、附件与隐私

源码及安装包不包含个人记录、账户配置、账单、健康数据、私人附件、API 密钥、浏览器会话或用户备份。新电脑首次打开时创建自己的资料库；GitHub 下载不能恢复个人数据。

- 业务数据目录：`~/Library/Application Support/GaoSeries/Monthly/`。
- 数据库或小组件镜像：`~/Library/Group Containers/5G96498KGJ.com.gaoseries.GaoYueGong/`。
- 设置保存在本应用的 UserDefaults 域；凭据由 macOS 钥匙串管理，不导出到普通备份文件。
- 公开安装包会删除本机编译路径、源文件索引及扩展属性，再重新签名。签名证书的公开身份信息随软件发布，签名私钥不在仓库或安装包中。

真实业务历史完整保留。界面采用分页或归档减轻加载；游戏事件最多保留 300 条、抽取记录最多 200 条、词元账户显示采样最多 300 条，累计收益、余额、保底计数、库存与游戏进度独立保存。

## 数据迁移与恢复

V4.0 从整合版拆分时保留业务历史、余额、库存、游戏进度、设置和全部附件。独立应用继续使用各自的数据目录，升级或替换应用程序不会删除这些数据。

在设置的数据页导出“完整资料 ZIP 备份”。恢复备份可迁移本应用的资料、App Group 镜像、设置以及已管理的 PDF、Word、照片等附件。备份使用逐文件 SHA-256 校验与 SQLite WAL 一致快照，恢复前保存安全副本；待下次启动应用时应用恢复。备份必须来自同一应用，不能将另外一个模块的备份直接导入。钥匙串凭据需在新电脑重新配置。

迁移临时副本不属于程序运行依赖，确认数据与附件完整后可自行清理。个人备份应单独保管，不应放进源码目录或上传公开仓库。

## 从源码构建

需要完整 Xcode、Python 3 和 Apple Silicon Mac。默认脚本使用项目配置的开发签名身份；自行构建需使用自己的 Apple Development 证书，并相应调整签名团队、App Group 权限及小组件工程配置。

```sh
./scripts/build.sh
./scripts/package.sh
./scripts/install.sh
```

通过环境变量 `GAO_SIGNING_IDENTITY` 可指定签名证书。修改团队后也需调整 `scripts/install.sh` 中的团队检查。`dist/` 存放本地发行 ZIP 和校验文件，不提交到 Git；上传到 GitHub Releases。

- `Sources/`、`Shared/`（如有）与 `Module.swift`：业务和游戏逻辑。
- `GameWorld/` 与 `Resources/`：场景、模型、贴图和其他资源。
- `Host/`：独立入口、设置、完整备份和联动服务。
- `Widgets/`：小组件；`Tests/`：回归验证。

## V4.02 更新

- 小组件分开显示真实「资料」保存时间与成功「读库」时间，读取旧数据或无变化打卡不会制造新的资料时间。
- 主应用与两种小组件共用同一 App Group 下的 `Monthly/monthly.sqlite`，沿用原 schema、设置与钥匙串。
- 在业务时区提前生成有限的午夜派生条目；主应用激活、跨日、时区/时钟变化及唤醒时重读。系统实际刷新时机由 WidgetKit 决定，不保证固定分钟数。
- 忙碌、缺失、损坏或不兼容资料不会初始化空库。存在最后有效缓存时明确标注缓存、隐藏详细名称金额并停用打卡；没有有效缓存时显示资料不可用。
- 更新请求按两种 widget kind 分别登记。系统请求 Timeline 后记录成功读库时间、资料摘要、缓存发布和失败原因；读取回执不能证明桌面已经绘制。
- 仅对真正首次使用的空目录允许主应用初始化；恢复/清空失败会明确报错，不再静默显示成功。

缓存和读取诊断位于 App Group 的 `Monthly/WidgetSync/`，属于私人资料，不提交或上传 GitHub。缓存采用校验和、跨进程发布锁与原子替换，只有成功读到可用资料后才发布。失败保留重试状态；最多保存 80 条读取回执。`pending-refresh.json` 的确认仅代表相应 kind 读到了请求的资料版本，不代表所有实例已刷新；多个尺寸的实际显示仍需逐一核查。

验证范围：静态/编译检查及隔离数据库、并发、跨日/跨月/时区、缓存故障和权益测试。遵循默认不自动冒烟的偏好，不会为测试启动应用、浏览器、模拟器或测试窗口。新增/编辑/删除真实记录、桌面实例、重启和睡眠唤醒的实际显示与延迟需要另行人工验收。

可运行 `python3 scripts/diagnose_widgets.py --output 验证记录/widget-diagnostics.json` 保存本机只读证据。命令不会启动应用、触发领取或请求刷新；输出包含私人资料元数据，请勿上传。

## 版本更新

版本以 `Info.plist` 为准。后续功能改动仅更新受影响的应用，默认版本 +0.01、构建号 +1；明确要求保持版本号的修订沿用原版本。先核验用户资料，再安装新程序并检查记录、附件和游戏进度，成功后清理旧程序、安装包与中间构建。程序资源与用户资料须分别处理，不能用清理构建目录的方式删除用户数据。

第三方组件和资源保留各自许可，详情见 `Resources/` 中的许可、来源说明与补丁记录。
